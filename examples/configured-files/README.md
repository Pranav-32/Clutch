# Generated version and configuration headers

Requires Clutch, a C++17 compiler and a compatible build executor. No interpreter
is needed. From this directory:

```sh
clutch .
clutch run
clutch . --release
clutch run --release
```

`VERSION` supplies `1.2.3`. Clutch replaces the template's named tokens, writes
`generated/<project-key>/build_info.hpp` in the selected build directory, and adds
that directory to the project's include paths. `@@` produces a literal `@`.
Custom values are literal text, so quote/escape them for the output language.
Edit `MESSAGE` or `VERSION`, configure again, then run to see the new values.

With `git_version = true`, source archives and projects without their own Git
repository print a `+source` version. To try commit/tag identity, copy this entire
example outside the Clutch checkout and create a Git repository there. Configure
once to create `clutch.lock`, commit the source files and lock, and tag that
commit `v1.2.3`. Run again to print the clean matching release version. The
example's `.gitignore` keeps generated profile/cache directories out of Git.
Later commits or edits add development/dirty identity.
The parent Clutch repository is not used as this example's repository.

Git identity is refreshed by builds; unchanged generated bytes retain timestamps.
Template or version-file edits require configuration. Each profile and workspace
project has its own generated include namespace. See [configured files](../../docs/manifest.md#configured-files)
for reserved variables, limits and failure behavior.
